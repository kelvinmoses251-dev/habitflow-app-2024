# Batch 2: Home Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship roadmap items 11 to 20: today's list on the first screen, faster completion, and a Home that organises itself (sections, time of day, reorder, swipe, day browser, filters, focus view).

**Architecture:** `renderHabits()` in `app.js` is one long function that builds every row. Task 3 splits it into a pure row builder (`habitRowHTML`) and a section renderer, and every later task builds on those. New Home behaviour that is independent of Firebase (gestures, reorder maths, day helpers) goes in a new top-level module `home.js`, so it can be unit-tested with `node --test`. Data changes are additive: one optional habit field, `timeOfDay`.

**Tech Stack:** Plain HTML, CSS, ES modules, Firebase. Tests: `node tests/smoke.js`, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-24-habitly-100-improvements-design.md`

## Global Constraints

- Everything in batch 1's Global Constraints still applies (no emoji, gradients, glow, blur, looping animation; light and dark; 320px to 1280px; motion one-shot, at most 240ms, off under reduced motion; 44px touch targets; tokens only).
- **Crowded-Home rule** (spec anti-goal), enforced by a test added in Task 1 and kept green by every later task: for an account with habits, the first habit row starts within 320px of the top of the screen at 375x667 and at 390x844.
- **Nothing gets between a tap and its result.** No new dialog, sheet or prompt may block completing a habit.
- Old habits keep working with no migration: every new field is optional and absent means today's behaviour.
- Completion rules are unchanged: a completion can be undone for one hour; past days are read-only.
- Each task: failing test first, the change, whole suite green, one row in `IMPROVEMENTS.md` (R12 onward, under `### Roadmap batch 2: Home`), one commit. Bump `?v=` for changed shipped files in all three HTML pages.
- New shipped files sit at the project root (`tools/deploy.js` publishes root files and `fonts/`).
- Owner decision recorded 24 November 2026: item 15 is approved (one tap with Undo is the default).

## Review Focus

1. **A habit list of 30 or more**: sections, dots, filters and drag must stay responsive and never cause horizontal scroll at 320px.
2. **Touch and scroll conflicts**: swiping a row or dragging to reorder must not break vertical scrolling of the page, and a vertical scroll must never complete a habit by accident.
3. **Keyboard and screen-reader parity**: every gesture (swipe, drag, collapse, day browser, focus view) has a button or key that does the same thing, with a name.
4. **Undo correctness**: Undo after a one-tap completion restores XP, the daily bonus state and the streak exactly, including offline.
5. **Stale state across accounts and days**: collapsed state, filters, the browsed day and focus view reset sensibly on sign-out, and the app rolls over cleanly at midnight while open.

### Task 4: Today grouped by time of day (roadmap 12)

**Interfaces:** optional habit field `timeOfDay: 'morning' | 'afternoon' | 'evening'` (absent = anytime). `home.js` `timeSlot(h): 'morning'|'afternoon'|'evening'|'any'`. Group headers `<li class="group-head" role="presentation">` with a line icon and label appear only when at least one daily habit has a time; order: Morning, Afternoon, Evening, Any time. The group that matches the current time of day (before 12, before 17, after) is listed first.

- [ ] Unit test (`tests/home.test.js`): `timeSlot` for each value, absent, and garbage.
- [ ] Test ("home: Today is grouped by time of day"): no headers when no habit has a time; with morning and evening habits, headers appear in order with the current slot first (clock stubbed); a new habit saved with Evening lands under Evening; the crowded-Home rule still holds with headers (headers are at most 28px tall); `privacy.html` mentions the time of day in what a habit stores.

- [ ] Test ("home: each daily row shows its last seven days"): pattern for a seeded history is exact; label count is right; a habit created three days ago has four `.na`; weekly rows have no dots; no horizontal scroll at 320px with a 60-character name.

### Task 6: Drag to reorder (roadmap 13)

**Interfaces:** `home.js` `moveItem(ids, from, to): string[]` and `orderBetween(prev, next): number` (midpoint; `prev`/`next` may be undefined). `attachReorder(listEl, { onMove(id, beforeId) })`. A grip button `.row-grip` (`aria-label="Reorder NAME"`) on each row: visible on hover or focus with a mouse, always on touch. Pointer drag on the grip moves the row (a placeholder shows the drop position; the page auto-scrolls near the edges); keyboard: with the grip focused, ArrowUp/ArrowDown move the row one place and a live region announces "Moved to position 2 of 6". Only the moved habit's `order` is written. While a habit is dragged, "done habits sink to the bottom" still applies after drop: reordering works within the not-done group and within the done group.

- [ ] Unit tests: `moveItem` edges; `orderBetween` at start, end, between, and when neighbours are equal (falls back to renumbering, returned as a list of writes).
- [ ] Test ("home: habits can be reordered by drag and by keyboard"): pointer drag of row 3 above row 1 changes DOM order and writes exactly one `order`; reload keeps it; keyboard ArrowUp does the same and announces; dragging does not tick a habit; grips are not shown in read-only day view (Task 8).
- [ ] Suite green; ledger R17; commit.

### Task 7: Swipe a row (roadmap 14)

**Interfaces:** `home.js` `attachSwipe(listEl, { onComplete(id), onReveal(id) })`. On touch-size screens (`max-width: 640px`): a horizontal drag of more than 72px to the right completes (or, if already done and unlocked, un-completes) the habit; to the left it reveals the row's actions (timer, edit if allowed, remove). The gesture starts only after 12px of mostly horizontal movement, so vertical scrolling is never taken over; rows use `touch-action: pan-y`. On phones the action buttons are no longer always visible: each row has a "More" button `.row-more` (`aria-label="More actions for NAME"`, `aria-expanded`) that reveals the same actions without a gesture. Only one row is revealed at a time; tapping elsewhere closes it.

- [ ] Test ("home: rows can be swiped, and everything a swipe does has a button"): swipe right completes with the Task 2 toast; a 30px drag does nothing; a mostly vertical drag does nothing; swipe left reveals three actions and a second row's reveal closes the first; the More button does the same and is 44px; on desktop there is no More button and hover actions work as before; a locked completed row cannot be swiped back.
- [ ] Suite green; ledger R18; commit.

### Task 8: Day browser (roadmap 16)

**Interfaces:** `home.js` `habitsOnDay(habits, day): { habit, done }[]` (daily habits that existed on that day). The Today card header gets `#day-prev` and `#day-next` buttons (`aria-label="Previous day"` / `"Next day"`) around the title; `viewDay` state in `app.js` (default today). Viewing a past day: the title reads the weekday and date, a quiet line says "You are looking at a past day. It cannot be changed." with a **Back to today** button, rows are read-only (checkboxes `disabled`, no grips, no swipe, no actions), the week and month cards hide, and `#day-next` is disabled on today. Keyboard: ArrowLeft / ArrowRight when the header buttons are focused. Limit: 60 days back. Tapping a day in the week strip jumps to that day.

- [ ] Unit test: `habitsOnDay` excludes habits created later and soft-deleted ones; done flags.
- [ ] Test ("home: past days can be browsed but not changed"): yesterday shows yesterday's ticks; clicking a checkbox there changes nothing in the database; Back to today restores everything; the next button is disabled on today; the view returns to today on sign-out and when the date rolls over.
- [ ] Suite green; ledger R19; commit.

### Task 9: Filter chips and search (roadmap 18)

**Interfaces:** `home.js` `matchesFilter(h, { category, text }): boolean`. A filter bar `#home-filter` inside the Today card, shown only when the account has more than eight habits: a search field (`aria-label="Search habits"`) and one chip per category in use (`aria-pressed`), plus "All". It filters all three lists; when nothing matches, a line "No habits match." with a **Clear** button. The filter is not persisted and resets on sign-out. The crowded-Home rule is measured with the bar present (bar is at most 44px tall, chips scroll sideways inside it).

- [ ] Unit test: text match is case- and accent-insensitive; category match; both.
- [ ] Test ("home: a long list can be filtered"): eight habits → no bar; nine → bar; typing filters; a chip filters and is pressed; Clear restores; the first row is still within 320px with nine habits and the bar.
- [ ] Suite green; ledger R20; commit.

### Task 10: Focus view (roadmap 20)

**Interfaces:** a **Focus** button `#focus-open` in the Today header (hidden with fewer than two open daily habits). It opens `#focus-view`, a full-screen layer (`role="dialog"`, `aria-modal`, `aria-label="Focus"`, part of `watchDialogs`, `data-sticky`) showing one open habit at a time: category chip, name in the display serif, its streak, and three actions: **Done** (completes through the Task 2 path, then advances), **Skip** (advances, no change), **Start timer** (opens the existing timer for that habit). A progress line "2 of 5" and an **Exit** button. When none are left it shows "That is everything for today." and closes on **Finish**. Keyboard: Enter = Done, ArrowRight = Skip, Escape = Exit.

- [ ] Test ("home: focus view walks through the open habits one at a time"): opens on the first open habit in list order; Done completes it and shows the next; Skip does not complete; the last one leads to the finished message; Exit returns focus to the Focus button; the button is hidden with one open habit; works at 320px without scroll.
- [ ] Suite green; ledger R21; commit.
